# LATCH学習教科書(docs/learn/)

- 種別: 参照(この教科書の使い方と構成の説明)
- 読み手: プログラミング学習中のあなた。前提知識は第1章から積み上げるので、何も知らない状態で始めて大丈夫です
- 最終更新: 2026-09-29(M2 ws-1「イベント駆動基盤」のマージに同期。第9章を新設し、
  第1章の容器数・コマンド・テスト件数を現況へ更新)

## この教科書は何をするものか

このリポジトリには、LATCHというサービスの**仕様**(何を作るか)、**記録**(どう作ったか)、
**コード**(実際の動作)があります。この教科書は、その3つを読み解くための橋です。
「コードを読めるようになる」ことを、読むだけではなく動かす・壊す・確かめるを交えて
目指します。実装が進むと、教科書も一緒に育ちます(下記「維持のしくみ」)。

## 学習の進め方: 3つの原則

1. **読む**: 章の順路(下記)に沿って通読する。専門用語は必ずその場で定義してあるので、
   分からなくなったら定義の場所に戻る
2. **動かす**: Labでは必ず自分の手でコマンドを打つ。コピペより打ち直しが定着する
3. **記録する**: `my-notes.md` を自分用に作り、「わかったこと」と「疑問」を書き溜める。
   自分の言葉で書けたことが、理解の本当の試験です

## 読む順路(依存順)

下の順で読むと、前提知識が積み上がります。各項目に「読み終えるとできるようになること」を
付けました。すでにできることがあれば読み飛ばして構いません。

| 順 | ファイル | 読み終えるとできるようになること |
|---|---|---|
| 1 | `00-environment.md`(第1章 全体像) | LATCHの全体像と、Docker・uv・FastAPI・DB・Redis・テスト・git が「何の問題を解く道具か」を説明できる |
| 2 | `labs/lab1-observe.md`(Lab 1 観察) | 動いているシステムを、curl・ログ・psql・redis-cli・pytest の5つの窓から観察できる |
| 3 | `01-reading-paths.md`(第2章 コードの読み方) | `/health` が返るまでをコードで追い、デコレータ・DI・フィクスチャの実体を掴む |
| 4 | `concepts/clock-and-testing.md`(第3章 Clockとテスト) | このプロジェクトの核心設計を、Python基礎から積んで完全に理解する |
| 5 | `labs/lab2-break-it.md`(Lab 2 壊して学ぶ) | 「変えて→予測→確かめる」の開発ループを体で覚える |
| 6 | `concepts/04-users-write-path.md`(第4章 書き込みの経路) | POST /v1/users をルータ→サービス→SQLの3層で追い、検証・DB制約・エラーの意味づけを説明できる |
| 7 | `concepts/05-intents-parse.md`(第5章 LLM境界) | LLM出力の検証・422/503の切替・Protocol・スタブの役割を説明できる |

| 9 | `concepts/07-rate-limit.md`(第7章 レート制限) | 数える場所の住み分け(Redis/DB)とJSTバケットによるリセットの工夫・429/422の使い分けを説明できる |

## Diátaxis(ディアタクシス): 教科書の4つの材料

この教科書は、ドキュメント作法の標準である Diátaxis(https://diataxis.fr/)の分類に従い、
性質の違う文書を混ぜないようにしています。

| 種別 | 読み手の問い | この教科書での置き場所 |
|---|---|---|
| チュートリアル(学習) | 「教えて」 | `labs/` — 手を動かして必ず成功体験を得る。**手順は実行検証済みのものだけを書く** |
| 手順書(作業) | 「どうやる?」 | `howtos/` — 特定の目的を達成するレシピ。目的ができたときだけ作る |
| 参照(辞書) | 「何これは?」 | 本体は `docs/01〜12`(仕様書)とコード。教科書はそこへの案内のみを置く |
| 解説(理解) | 「なぜ?」 | `00-`・`01-`(章)と `concepts/` — 設計の意図と背景を、前提から積んで説明する |

各ファイルの先頭に「種別: 〜」と書いてあるのはこの約束のためです。

## 教科書としての約束

- **前提から積む**: 新しい概念は、必ず既に出た概念の上に置く。飛ばした先に出てきたら、
  該当章に戻る案内を書く
- **専門用語は機能→名前の順**: まず現象を平易に説明し、それから「これを〜と呼ぶ」と名前を渡す
- **実在だけを書く**: コード引用は実際のファイル・行から。期待される出力は実行して確認したもの。
  確認していないことは断定しない
- **章末に用語集と確認問題**を置く。解答は用意しない(自分の言葉で答えられなければ、
  それは読み返すべき節の地図)

## 自分のノートの使い方

`my-notes.md` という名前で自分用のファイルを作ってください(コミットするかは自由)。

```markdown
# 学習ノート

## わかったこと
- (例)/health の server_time は app.state.clock の時計由来。差し替え点は1つ

## 疑問
- (例)lifespan って何のためにある? → 第2章で出てきたら解消する
```

疑問が章を読んでも解消しないときは、そのままスーパーバイザー(Claude)に質問してください。
質問と回答は、教科書を育てる材料になります。

## 維持のしくみ(開発ワークフローとの統合)

実装の各作業単位が main にマージされたあと、スーパーバイザーが **agent4(学習資産同期)**
を起動し、この教科書を新しいコードに合わせて更新します。更新の規約(種別・教科書としての
約束・検証方法)は `.claude/prompts/agent4-learn.md` に一元化されており、
**セッションが変わっても同じ基準で保守されます**。日本語の文書としての品質は
**natural-japanese スキルの使用が必須**として規約に組み込まれています(2026-09-27
オーナー指示)。

「難しすぎる」「もっと詳しく」も、いつでも遠慮なく伝えてください。教材の調整も
作業単位として扱います。
