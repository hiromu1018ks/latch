# LATCH 学習資産(docs/learn/)

- 種別: 参照(このディレクトリの使い方と規約)
- 読み手: プログラミング学習中のあなた(初心者向けに書きます。専門用語は初出時に一文で定義します)
- 対象範囲: 現在は M0(開発基盤)まで。実装が進むと一緒に育ちます(下記「維持のしくみ」)

## このディレクトリは何

このリポジトリに実装されたコードと環境から**学ぶための教材**です。
仕様書(`docs/01〜12`)が「何を作るか」を決め、`docs/plans/` が「どう作ったか」を記録し、
コードが「実際の動作」です。`docs/learn/` はその3つへの**橋**であり、読む順路を提供します。

## Diátaxis(ディアタクシス)という考え方

ドキュメントは「読み手の必要」によって4種類に分け、**混ぜない**のが良いとされる框架です
(https://diataxis.fr/ 。多くのプロジェクトの標準になっています)。

| 種別 | 読み手の問い | このrepoでの置き場所 |
|---|---|---|
| チュートリアル(学習) | 「教えて」 | `labs/` — 手を動かして必ず成功体験を得る実験 |
| 手順書(作業) | 「どうやる?」 | `howtos/` — 特定の目的を達成するレシピ(必要になったら作る) |
| 参照(辞書) | 「何これは?」 | **learn/には置かない**。本体は `docs/01〜12` とコード。learn/はそこへの案内のみ |
| 解説(理解) | 「なぜそうなる?」 | `concepts/` と `01-reading-paths.md` — 設計の意図と背景 |

規約:

- 各ファイルの先頭に「種別: 〜」を必ず書き、1ファイル1種別に保つ
- チュートリアル(labs)は説明を最小限にし、詳細は concepts へリンクする
- 参照(仕様の正確な値など)は learn/ に複製せず docs/01〜12 へのリンクで済ませる(二重管理を防ぐ)

## 読む順路(依存順)

「何を先に読むか」を依存順に並べています。番号の若いものが前提知識です。

1. `00-environment.md` — 全体像: どんな道具がどう組み合わさっているか
2. `labs/lab1-observe.md` — 動いているものを観察する(最初の成功体験)
3. `01-reading-paths.md` のトレース1 — 「/health が返るまで」をコードで追う
4. `concepts/clock-and-testing.md` — このリポジトリで一番の見どころ(Clock と テスト)
5. `labs/lab2-break-it.md` — コードをわざと壊して学ぶ
6. 以降は興味に応じて: 追加のトレース・概念ノート(実装の進行とともに増えます)

## 自分のノートを付けよう

読むだけでなく、自分の言葉でメモを残すと定着が早くなります
(「自分が理解した依存関係の地図」は、どの教材より価値があります)。
`my-notes.md` を自分用に作って、理解したこと・疑問を書き溜めてください。

```markdown
## わかったこと
- /health は main.py の health() が返している。時刻は Clock 経由

## 疑問
- lifespan って何のためにある?
```

## 維持のしくみ(開発ワークフローとの統合)

- 実装の各作業単位が main にマージされたあと、スーパーバイザーが **agent4(学習資産同期)**
  を起動し、`docs/learn/` を新しいコードに合わせて更新します
- 更新の規約(種別・文体・検証方法)は `.claude/prompts/agent4-learn.md` に一元化されており、
  **セッションが変わっても同じ基準で保守されます**
- 学習者の感想・要望はいつでも歓迎します。docs/learn/ の内容が難しすぎる・足りない場合は
  そのまま伝えてください。教材の調整も作業単位として扱います
