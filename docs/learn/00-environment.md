## LATCH とは何か(1段落)

LATCH は「やりたいこと(Intent)を登録すると、条件の合う人とマッチングしてくれる」サービスです。
ユーザーは Web アプリで「今週末、天文館周辺で飲みに行きたい」のようなIntentを送り、
サーバーが保存・解析・マッチングをして、成立したら提案を届けます。
このリポジトリはその**サーバー側(バックエンド)**と仕様書・設計記録を扱います。

## 登場する道具(それぞれ「何で必要か」)

| 道具 | 一言でいうと | このプロジェクトでの役割 |
|---|---|---|
| Python | プログラミング言語 | すべてのサーバーコードの言語(バージョン3.13) |
| uv | Pythonの依存管理ツール | ライブラリの導入と固定。`pip`+`venv`の代替で、速くて決定的 |
| FastAPI | Webフレームワーク | 「URLが呼ばれたらこの関数を実行」を書くための道具(APIの心臓部) |
| uvicorn | サーバー実行器 | FastAPIで書いたアプリを実際に動かし、ポート8000で待ち受ける |
| PostgreSQL(+PostGIS) | データベース | データの永続保存(users・intents等の表。PostGISは位置情報の拡張) |
| Redis | 高速なキーバリュー保管 | 認証トークンの失効リスト等、細かくて速い読み書きが要るもの |
| Docker / compose | 「容器」に閉じ込えて動かす仕組み | db・redis・api・workerの4サービスを一括で起動・管理 |
| pytest | テスト実行ツール | コードの振る舞いを自動検証(現在全270試験・数秒で完了) |
| git / GitHub | 変更履歴の管理 | 各機能が細かいコミットに分かれており、履歴自体が学習教材 |

│   │   ├── llm/           AI(LLM)呼び出しの単一経路

## よく使うコマンド(Makefile 経由)

すべてリポジトリのルートで実行します。

| コマンド | 何をするか |
|---|---|
| `make setup` | Pythonの依存を導入(初回や、依存が変わった後に) |
| `make up` | db・redis・api・worker の4サービスを起動(常設) |
| `make ps` | 4サービスの状態一覧 |
| `make logs` | 4サービスのログを流し見る(Ctrl+Cで停止) |
| `make test` | unit試験(速い。コミット毎に回す。約2秒) |
| `make test-ci` | unit+integration(実DB・実Redisを使う試験込み) |
| `make lint` | コードの書式・静的検査(ruff) |
| `make migrate` | DBの表定義を最新版に更新(Alembic) |
| `make geo-verify` | 地名⇔座標変換の動作確認 |

## 学習時の注意(重要)

- **`make test-ci` を実行すると、DBの地物データ(鹿児島の実データ609行)が試験用の偽データに
  置き換わります**。元に戻すには `make geo-import` を再実行します(数分)。
  これは仕様なので焦らないでください(運用メモをSTATUS.mdに記録済み)
- **main ブランチは「常に動く状態」を保つ場所**です。実験でコードをいじるときは
  `lab2-break-it.md` の安全手順に従ってください
- 実行環境の docker コマンドは `docker compose ...` 形式です(v2構文)
