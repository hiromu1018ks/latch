# 改版メモ: 提案閾値0.80→0.60とフォールバックモデル変更(Sonnet 5→Haiku 4.5)

- 改版日: 2026-09-30
- 決定者: オーナー(本メモはスーパーバイザーが記録)
- 対象文書: 01 v0.6 / 04 v0.6 / 05 v0.6 / 06 v0.6 / 07 v0.7 / 09 v0.6 /
  11 v0.4 / 12 v0.3 / T1資料 v0.3

## 1. 決定の経緯

M2 ws-8マージ後、G2日本語評価をTypeSafe Jev(jev-1.13.0)のみで実施した
(520ペア全件・失敗0・296秒・実コスト$0.03。証拠:
docs/testassets/results/g2-jev-result-20260930-134810.yaml)。

結果は次のとおりだった。

| 閾値 | 提案数 | Precision | Recall |
|---|---|---|---|
| 0.80(当時の運用閾値) | 1 | 1.00 | 0.5% |
| 0.70 | 13 | 0.85 | 5.3% |
| 0.60 | 39 | 0.80 | 14.9% |
| 0.50 | 74 | 0.70 | 25.0% |

MutualScoreの最大値が0.81で、運用閾値0.80では提案がほぼ発生しない。
一方でAUC(分布の分離度)=0.75と並び順の質は偶然(0.5)を明確に超え、
ECE=0.091・Brier=0.210と較正も良好である。ゴールドセット期待バンドとの
照合でもズレの8割が「期待high→実際mid/low」の一方向で、日本語入力に対して
確率の水準が体系的に低く出る(公式のCJK留保の顕在化)と解釈した。

これを受けてオーナーが2点を決定した(2026-09-30)。

1. **第一候補はJevのまま、提案閾値を0.80から0.60へ下げる**
   (0.50はA/B試験の処置群候補として残す)
2. **フォールバックLLMからSonnet 5を外し、Haiku 4.5へ変更する**
   (理由はコスト。マネタイズ前のサービスで高単価モデルは排除する。
   Parserと同一モデルのため契約・API鍵を共用できる)

## 2. 変更点の一覧

### 閾値0.80→0.60(運用値)

- 01: §24(D-01初期値)・第15節(グループ閾値)・第18節(A/B手順)・
  D-01/D-06解消記録
- 06: 第1節(閾値との比較)・第6節(L>=0.60)・第7節(集約規則)・
  第10節(保留キュー)・D-06一覧表・D-07の閾値近傍ノイズ例(0.59→0.601)
- 09: 仮説3のOffline合格線を「閾値0.60でのPrecision 0.60以上」へ・
  §4.2 A/Bを対照0.60/処置0.50へ・Offline 3閾値を0.50/0.60/0.70へ・
  判定不能時の持続規定を0.60維持へ
- 11: A/B計画(0.60 vs 0.50)と持続規定
- 12: C7・M2スコープ7の記述
- 05: match_levelのlow区分に関するA/B例値(0.70→0.50)。区分の境界
  (high≥0.90・medium≥0.80)は表示用の区切りであり提案閾値と独立のため不変

### フォールバックSonnet 5→Haiku 4.5

- 01(D-14解消記録)・04(D-14採用記録・技術スタック表)・06(第5節・D-15)・
  07(第1節表・第4節)・09(第4節のフォールバック評価の扱い)・12(冒頭・
  M2スコープ6・リスク表の繰上げ先)・T1(推奨・切替順序・コスト)
- 切替条件(429・529・timeout)・出力形式(System One互換answers)・
  circuit breaker・skipped保留の挙動はすべて不変。モデル名のみの変更
- 09 v0.6では、フォールバックの同一ゴールドセット評価を「第一候補が
  不合格で比較が必要な場合のみ」に変更した(コスト方針。既定では実施しない)

## 3. コストの再試算(T1 v0.3・検算つき)

- フォールバック全件継続(1ヶ月): 20万回×(3,000入力×$1+300出力×$5)/100万
  = **$900/月**(Sonnet 5時の$1,800から半減)
- Jev回数上限(60万回)到達時のフォールバック: $2,700(Sonnet 5時$5,400から半減)
- 通常時(フォールバック発火なし)は従来どおり約$140/月で不変

## 4. 実装への影響と追随

- コード側の追随は小規模単位で実施: フォールバックモデル定数1箇所
  (backend/src/latch/llm/anthropic_jev.py)とg2gateの測定閾値
  (0.70/0.80/0.90→0.50/0.60/0.70)、およびピン試験の期待値
- 提案閾値0.60はコード上の定数(06 §6の閾値)として実装済みのため
  あわせて更新する
- G2合格基準書(docs/testassets/g2-jev-acceptance-criteria.md)は
  v0.2へ改正する(必須①Precision@0.60≥0.60・②AUC≥0.70に加え、
  提案数の下限を新設。v0.1で「Precisionだけでn=1の退化合格が通る」
  抜け穴が判明したため)

## 5. 評価の生データに関する注記

本改版の根拠となった520ペアの評価は、閾値0.60での値(precision 0.795・
recall 0.149・n=39)をper_pair記録から算出している。レポート本体の
thresholds欄は当時の測定閾値(0.70/0.80/0.90)で書かれており、
g2gateの閾値更新後に再実行すれば$0.03で閾値0.60を含む正式証拠が得られる
(G2判定時に実施するかはスーパーバイザー判断)。
